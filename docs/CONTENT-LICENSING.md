# Контент и лицензии

Код проекта — MIT. **Игровой контент живёт по другим правилам**, и это важнее, чем
кажется: именно на контенте чаще всего ломаются VTT-проекты.

> Это не юридическая консультация. Перед публикацией контента проверьте лицензию
> первоисточника сами.

## 1. Что можно класть в репозиторий

| Источник | Лицензия | Можно | Условия |
|---|---|---|---|
| **SRD 5.1** | CC-BY-4.0 | да | атрибуция Wizards of the Coast |
| **SRD 5.2** (правила 2024) | CC-BY-4.0 | да | атрибуция Wizards of the Coast |
| Собственные тексты и правила | ваша | да | укажите автора |
| Собственные карты/токены | ваша | да | укажите лицензию в манифесте |
| Контент с явной открытой лицензией | по лицензии | да | сохранить уведомление |
| Купленные книги/PDF | — | **нет** | даже «для личного использования» в репозиторий нельзя |
| Арт из книг, логотипы | — | **нет** | товарные знаки и копирайт |

## 2. Что нельзя (даже если «в интернете лежит»)

- ❌ Товарные знаки: **D&D, Dungeons & Dragons, Forgotten Realms**, названия сеттингов,
  имена персонажей WotC, логотип.
- ❌ Монстров и существ вне SRD: **beholder, mind flayer, displacer beast** и т. п.
- ❌ Тексты, таблицы и арт из платных книг (PHB, MM, DMG, приключения).
- ❌ Импорт и раздача платных компендиумов Foundry / Roll20 / Fantasy Grounds.
- ❌ Скрейпинг чужих сайтов и «переводы» без разрешения правообладателя.
- ❌ Шрифты без открытой лицензии (используем Inter / Noto / PT — OFL).

## 3. Формат пака

Контент поставляется отдельными паками, а не «зашит» в бинарник:

```json
{
  "id": "srd-5.2-basic",
  "name": "SRD 5.2 — базовые правила",
  "license": "CC-BY-4.0",
  "attribution": "Rules content based on the System Reference Document 5.2 by Wizards of the Coast LLC, licensed under CC-BY-4.0.",
  "spells": [ { "name": "…", "level": 1, "source": "srd-5.2", "…": "…" } ],
  "monsters": [ { "name": "…", "source": "srd-5.2", "…": "…" } ]
}
```

Обязательные поля:

- `license` — `CC-BY-4.0`, `private`, `CC0-1.0`, `MIT` или иная явная;
- `attribution` — непустое, если лицензия требует указания авторства;
- у каждой записи `source` — идентификатор пака-источника.

## 4. Текст атрибуции

Для SRD 5.2 (CC-BY-4.0):

> Rules content based on the System Reference Document 5.2 by Wizards of the Coast LLC,
> licensed under the Creative Commons Attribution 4.0 International License.

Текст должен быть виден пользователю (экран «О лицензиях» / README пака), а не только
лежать в комментарии кода.

## 5. Пользовательские данные

Приложение позволяет ГМу импортировать **свои** файлы. Это его ответственность:
мы не хостим, не распространяем и не синхронизируем этот контент через свои сервисы.
Репозиторий проекта не должен содержать пользовательские паки с закрытым контентом.

## 6. Чек-лист для PR с контентом

- [ ] Указан `license` и, где нужно, `attribution`.
- [ ] Ни одной записи вне SRD / собственных материалов.
- [ ] Нет названий и имён, защищённых товарным знаком.
- [ ] У каждой записи заполнен `source`.
- [ ] Проверено, что арт и шрифты имеют открытую лицензию.
- [ ] Запись корректно ищется через `ContentRegistry::search` и попадает в результат
      теста `content`-модуля.

## 7. Почему так строго

Показательный случай: в 2023 году сообщество VTT обсуждало смену лицензии OGL, и
проекты, «зашившие» чужой контент, рисковали всем. Модель «ядро + паки» даёт:

1. юридическую чистоту ядра;
2. возможность выпускать ядро под MIT;
3. ответственность за контент — на том, кто его ставит.
