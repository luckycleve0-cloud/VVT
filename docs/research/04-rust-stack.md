# 04. Rust-стек на 2026: что брать

> Версии проверены по crates.io API 25.11.2026. Статус «зрелое» = стабильный API,
> большая аудитория, живая поддержка.

---

## 1. Проверенные факты (ноябрь 2026)

| Крейт | Версия | Дата | Комментарий |
|---|---|---|---|
| `bevy` | **0.20.1** | 28.10.2026 | ECS-движок, edition 2024, MSRV 1.97 |
| `egui` | **0.37.0** | 15.10.2026 | immediate-mode GUI, MSRV 1.95 |
| `iroh` | **1.5.0** | 19.11.2026 | P2P QUIC; 1.0 вышел в июне 2026, стабильная серия |
| `quinn` | **0.11.12** | 14.09.2026 | QUIC; MSRV 1.85, зрелый |

Важное из метаданных `iroh 1.5.0`:
- фича `portmapper` включена **по умолчанию** — то есть UPnP/NAT-PMP/PCP уже встроены;
- `iroh-relay` в зависимостях — релей есть из коробки;
- QUIC-реализация — `noq` (форк/эволюция quinn внутри iroh), а не `quinn` напрямую;
- NodeId = публичный ключ (ed25519), соединения по ключу, а не по IP.

Вывод: **лестница «LAN → direct+UPnP → hole punch → relay» из [03-сеть](../03-сеть-гм-хост.md)
реализуется одним крейтом.** Это главный технический вывод всего исследования.

Остальные версии в таблицах ниже — без точных номеров (меняются каждые пару месяцев);
перед стартом проекта зафиксировать `cargo add` на актуальных.

## 2. Рендер и UI: главный выбор

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **egui + свой wgpu-рендер стола** | мгновенный UI, простые панели/формы, без ECS-оверхеда, полный контроль над картой | immediate-mode не любит огромные таблицы/виртуализацию (решается), свой виджет-набор | **рекомендую для MVP** |
| **Bevy 0.20** | ECS, спрайты, камера, ассеты, UI, звук, picking — «из коробки»; 2D-сцена за вечер | API ломается каждые 3–4 месяца (0.x), тяжёлый бинарник, «движок для игры», а не для приложения | хорош, если планируется 3D/анимации |
| **Tauri + веб-фронт** | быстрый UI на HTML/CSS, знакомые инструменты | webview = не «нативно», тяжёлый рендер карты через canvas/WebGL, две технологии | нет: противоречит цели «быстро и нативно» |
| **iced / slint / dioxus** | декларативный UI, нативный | меньше экосистема для canvas-сцены, меньше примеров | нет |
| **wgpu напрямую + свой UI** | максимум контроля | писать весь UI самому = месяцы | нет |

**Рекомендация: гибрид.**
- `wgpu` — рендер сцены (карта, токены, туман, свет) в отдельном проходе;
- `egui` (через `egui-wgpu`/`eframe`-подобную интеграцию) — панели, листы, чат, диалоги;
- общий `winit`-цикл; сцена и UI рисуются в одном кадре.

Почему не Bevy: VTT — это на 60% форма/таблица/список, а не игра. ECS здесь только мешает,
а нестабильность API каждые полгода — прямой риск для соло-разработки.

## 3. Таблица: 2D-графика карты

| Задача | Крейт / подход |
|---|---|
| Батчинг спрайтов | свой инстансинг в wgpu (просто), либо `bevy_sprite` |
| Векторные линии (стены, шаблоны, линейка) | `lyon` (тесселяция) + заливка; альтернатива — SDF в шейдере |
| Кривые/скругления UI | `egui` рисует сам |
| Текст (в т.ч. кириллица) | `cosmic-text` (shape + fallback) либо встроенный в egui |
| Декодирование картинок | `image` (png/jpeg/webp/avif — проверить нативные бэкенды); `zune-image` как быстрый альтернативный декодер |
| Сжатые текстуры | KTX2/Basis через `ktx2` + `basis-universal` (для 8K-карт — экономия VRAM) |
| Туман/свет | полигоны на CPU (как Foundry) → маска в текстуре; шейдерное размытие краёв |
| Большие карты (>8K) | тайлы 1024/2048 px, ленивая подгрузка, мип-уровни |

> Осторожно: `vello` (GPU-вектор) красив, но API молодой и требует `wgpu`-совместимости —
> для MVP не нужен.

## 4. Сеть

| Крейт | Роль | Оценка |
|---|---|---|
| **`iroh` 1.5** | P2P QUIC + hole punching + релей + UPnP | **основной выбор**; даёт всю лестницу режимов |
| `iroh-relay` | свой релей (если захотим не зависеть от их инфраструктуры) | опционально, потом |
| `quinn` 0.11 | «чистый» QUIC, если строить свою лестницу | план B |
| `tokio` | рантайм | обязательно |
| `rustls` + `rcgen` | TLS-сертификаты для прямого режима | при прямом режиме без iroh |
| `mdns-sd` | обнаружение в LAN | P0-фича для домашних игр |
| `igd-next` | UPnP, если идём без iroh | дублирует iroh, не нужен |
| `webrtc`/`str0m` | только если понадобится браузерный клиент | не в MVP |

**Итог:** iroh + tokio + самодельный протокол сообщений поверх. Если iroh окажется
недостаточно гибким — падение до `quinn` + свои STUN/релей, но это +2–3 месяца.

## 5. Сериализация и протокол

| Задача | Выбор |
|---|---|
| Сообщения сети | `serde` + **`postcard`** (компактный, no_std, стабильный формат) |
| Состояние/снапшоты | `serde` + `bincode` 2.x или тот же postcard |
| Файл кампании | `serde` + `postcard` + `zstd` (сжать) |
| Совместимость версий | явный `version: u16` в заголовке + миграции |
| Zero-copy для больших | `rkyv` — только если реально упрёмся в производительность |

Никакого JSON в горячем пути (кроме отладки и конфигов).

## 6. Данные и хранилище

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **rusqlite (bundled)** | SQL, транзакции, **FTS5** для поиска, индексы, зрелость | линкует C-SQLite (+1 МБ, но `bundled` = без зависимостей) | **рекомендую** |
| `redb` | чистый Rust, встраиваемая KV, ACID | нет SQL/поиска, запросы вручную | альтернатива |
| `sled` | быстрый KV | репутация «beta, странные баги» | нет |
| JSON-файлы | просто | нет транзакций, большие кампании тормозят | только для настроек |

Схема: `campaigns.db` (SQLite) + папка `assets/` (файлы по хэшу) + `manifest`.
Поиск по компендиуму — FTS5 + `unicode61` (русский работает, но без стемминга; для
стемминга позже `stemmer`/`rust-stemmers`).

## 7. Ассеты

- `blake3` — хэш содержимого (быстрее SHA-256, есть на всех платформах).
- Каталог: `assets/blake3/ab/cd/<hash>` — дедупликация автоматически.
- Пак-файлы: `zip` или `tar` + `zstd` для импорта/экспорта кампаний.
- Память: `memmap2` для больших файлов, но текстуры всё равно в VRAM.
- Переупаковка при импорте: `image` + `webp`-энкодер (проверить качество/лицензии),
  ресайз до 4096 px, генерация миниатюр 256 px.

## 9. Остальное

## 11. Риски стека

| Риск | Вероятность | Митигация |
|---|---|---|
| bevy API churn (если выбрать) | высокая | выбрать egui+wgpu |
| wgpu на старых драйверах Intel/AMD | средняя | тест-матрица, fallback на GL? (wgpu умеет GL-бэкенд) |
| iroh меняет API между минорными | средняя | зафиксировать версию в `Cargo.toml`, абстракция `Transport` |
| opus/WebRTC в Rust болезненно | высокая | голос — в v1.1, через отдельный сервис-крейт |
| egui для сложных таблиц (лист персонажа) | средняя | виртуализация строк, кастомные виджеты |
| Код-сайнинг дорогой | высокая | начать без него (пользователи жмут «всё равно запустить»), купить к релизу |

## 12. Итоговый стек (рекомендация)

```
Платформа:   Windows 10/11 (x64), позже macOS/Linux
Язык:        Rust 2024 edition (MSRV ≥ 1.95)
Окно/ввод:   winit
Рендер:      wgpu (+ naga), lyon для линий, cosmic-text
UI:          egui (панели, листы, чат) поверх wgpu
Сеть:        iroh 1.x (QUIC + hole punching + relay + UPnP) + tokio
Протокол:    serde + postcard, версионирование в заголовке
Данные:      rusqlite (bundled, FTS5)
Ассеты:      blake3 + image + zstd, content-addressed
Аудио:       kira + symphonia (+ opus в v1.1)
Логи:        tracing
Тесты:       insta + proptest
Сборка:      cargo + NSIS/MSI, GitHub Actions matrix
```

Этот набор даёт: быстрый старт, один бинарник, отсутствие Node/браузера, полный контроль
над картой и сетью. Главная цена — писать UI и карту руками, а не «на готовом движке».
