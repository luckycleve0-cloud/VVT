**Вывод:** «просто работает» сегодня означает «чей-то облачный сервер». Мы хотим того же
удобства без облака — это и есть ниша.

## 2. Прямые признания конкурентов

- **TaleSpire (FAQ):** «лучший способ начать — централизованные серверы; в будущем хотим
  добавить peer-to-peer, чтобы наши серверы стали необязательны». Также: «если у нас не
  будет доступа к серверам, клиент бесполезен — это главный риск для сообщества».
- **Foundry (FAQ):** самостоятельный хостинг требует, чтобы игроки могли достучаться до
  машины ГМа; типовые проблемы сообщества — CGNAT, двойной NAT, блокировки провайдера.
- **Owlbear:** комната живёт на их серверах; самостоятельного хостинга нет, оффлайна нет.

## 3. Что это значит для нас

1. Наша модель **не уникальна по механике** (Foundry/FG так умеют), но **уникальна по
   подаче**: у конкурентов это «настройка», у нас — «кнопка».
2. Нужен **релей-фолбэк**, иначе 10–20% пользователей (мобильный интернет, CGNAT,
   общежития) не подключатся и уйдут.
3. Нужна **встроенная диагностика**: тип NAT, «порт закрыт», «попробуйте VPN» — иначе
   поддержка съест всё время.
4. Нужна совместимость с существующими VPN (Radmin/ZeroTier/Tailscale): режим «подключиться
   по IP:порт» и обнаружение в LAN — это гарантированный путь для самых сложных сетей.
5. Модель «ГМ = сервер» легальна и технически нормальна для P2P-игр; приватность IP —
   стандартное предупреждение, как в Hamachi.

## 4. Технические факты, на которые опирается план

- QUIC (RFC 9000) = TLS 1.3 + мультиплексирование стримов + ненадёжные датаграммы;
  решает head-of-line blocking, который мучает TCP-решения.
- `iroh` 1.5.0 (ноябрь 2026): P2P QUIC по публичному ключу, hole punching,
  фича `portmapper` (UPnP/NAT-PMP/PCP) включена по умолчанию, встроенный `iroh-relay`.
- `quinn` 0.11.12 — «чистый» QUIC-транспорт, если понадобится своя лестница NAT.
- Стандартный набор: STUN (узнать внешний адрес), ICE (перебор кандидатов),
  TURN/релей (когда пробить не удалось), mDNS (обнаружение в LAN).

## 5. Оценки, которые НЕ являются измеренными

| Оценка | Значение | Откуда |
|---|---|---|
| Доля сетей с рабочим UPnP | 60–80% | индустриальные оценки, не замер |
| Доля CGNAT у домашних провайдеров | 10–20% | оценка по отрасли |
| Добавка задержки через релей | +20–80 мс | типичные значения для релея в том же регионе |
| Трафик на сессию (6 игроков, без голоса) | 50–300 МБ | расчёт по размерам ассетов, не замер |

Эти числа нужно уточнить после первых 20 реальных сессий (метрики в приложении).
